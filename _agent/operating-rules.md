# 小说工作区 Agent 操作规则

日期：2026-06-25  
适用范围：`/Users/yao/Documents/小说项目`

## 1. 核心定位

本工作区是多本小说共用的创作操作台，不是某一本小说的专属目录。

Agent 在本工作区内执行任务时，应先判断任务属于哪一层：

- 工作区级任务：规划 agent、规划 skill、维护模板、整理共用规则、做跨项目调研。
- 单本小说级任务：整理某一本小说的设定、角色、大纲、正文、修订和导出。
- 外部参考级任务：检索资料、拆解公开作品、整理 GitHub 项目、记录写作方法。

如果用户没有明确指定某一本小说，Agent 不应擅自把任务归入任何现有或假想小说。

## 2. 根目录行为规则

在根目录下，Agent 默认只处理以下内容：

- `_agent/`：工作区规则、规划、流程图、路线图。
- `_skills/`：自定义 skill 草案和测试材料。
- `_templates/`：新小说项目模板。
- `_research/`：跨项目调研资料。
- 单本小说目录：用户明确创建或指定的小说项目。

Agent 在根目录不得做以下行为：

- 不直接写正文。
- 不把某本小说的世界观写进 `_agent/`。
- 不把市场调研结论直接写成任何小说的正式设定。
- 不把一个小说项目的角色、设定、伏笔复制到另一本小说，除非用户明确要求。

## 3. 任务分流规则

Agent 收到用户请求后，应先判断任务类型。

### 3.0 Agent / Skill 自动调用规则

每次执行任务前，Agent 必须自动检索并调取对应的 agent / skill，不需要用户额外强调。

执行顺序：

1. 先用 `novel-workspace-router` 判断任务层级、目标项目和写入边界。
2. 再按任务类型调用对应专项 skill：
   - 新建小说：`novel-project-initializer`
   - 设定、角色、术语、资料库：`novel-bible-manager`
   - 大纲、章纲、伏笔、时间线：`novel-plot-architect`
   - 正文草稿、场景、对白：`novel-draft-writer`
   - 文风、去 AI 味、角色声音：`novel-style-keeper`
   - 审稿、润色、改稿、节奏修订：`novel-revision-desk`
   - 连续性、设定冲突、状态漂移：`novel-continuity-checker`
   - 外部资料、考据、参考整理：`novel-research-scout`
   - 导出、打包、投稿版：`novel-export-packager`
3. 如果任务同时涉及多个方向，先调用会影响边界和事实的 skill，再调用写作或修订 skill。例如：先设定管理，再写正文；先连续性检查，再修订。
4. 如果本地项目内已有对应规范文件，必须先读取，例如 `05_修订与审校/风格修订.md`、`06_状态快照/已确认设定.md`、`03_剧情结构/章纲/`。
5. 如发现没有合适 skill，应说明缺口，并按现有工作区规则采用最接近的流程，不得跳过任务分流。

### 3.1 工作区规划任务

符合以下情况时，归为工作区规划任务：

- 用户提到 agent、skill、规则、模板、流程、工作区结构。
- 用户要求“规划”“搭建”“封装”“整理体系”。
- 用户没有指定某一本小说，但讨论的是长期写作系统。

处理方式：

1. 读取 `_agent/` 下相关文档。
2. 修改或新增工作区级文档。
3. 不写入任何单本小说目录。
4. 不展开具体剧情或世界观。

### 3.2 新小说初始化任务

符合以下情况时，归为新小说初始化任务：

- 用户说“新建一本小说”。
- 用户提供新书名。
- 用户要求“把这些想法整理成一个新项目”。

处理方式：

1. 确认小说项目名称。
2. 使用 `_templates/novel-project-template/` 创建目录结构。
3. 只填入用户已经提供的信息。
4. 对缺失内容保留空白或标记为待补充。
5. 不擅自补写世界观、人物和剧情。

### 3.3 单本小说维护任务

符合以下情况时，归为单本小说维护任务：

- 用户明确指定一本小说。
- 用户要求整理设定、角色、纲要、正文、审校或导出。
- 用户在某本小说目录中工作。

处理方式：

1. 定位目标小说目录。
2. 读取该项目的总纲、状态快照和相关资料库。
3. 只在该小说目录内写入内容。
4. 输出前说明将改动哪些文件。
5. 涉及核心设定变更时，先列出变更，等待用户确认。

### 3.4 外部参考任务

符合以下情况时，归为外部参考任务：

- 用户要求检索网络资料。
- 用户要求研究 GitHub 项目。
- 用户要求扫榜、拆文、整理方法论。
- 用户要求查某个现实知识点。

处理方式：

1. 标明资料来源和检索日期。
2. 先写入 `_research/` 或单本小说的 `07_参考资料/`。
3. 不直接改写为正式设定。
4. 明确区分事实资料、竞品观察、创作灵感和用户已确认内容。

## 4. 写入权限与确认规则

### 4.1 可以直接写入的内容

Agent 可以在不额外确认的情况下写入：

- 用户明确要求创建的规划文档。
- 用户明确要求创建的模板文件。
- 用户明确要求起草的 skill 草案。
- 已经确定为草稿性质的参考资料。
- 不改变小说事实的格式整理。

### 4.2 需要先确认的内容

以下内容必须先列出计划，等待用户确认后再写入：

- 修改某本小说的核心世界观。
- 修改角色命运、阵营、能力、身份、死亡、生还等关键事实。
- 修改主线结局或卷级结构。
- 删除已有正文、设定、角色档案或状态快照。
- 将待确认灵感升级为正式设定。
- 把外部调研结论写入小说圣经。

### 4.3 禁止自动覆盖的内容

Agent 不得自动覆盖：

- `已确认设定.md`
- `事实快照.md`
- `角色状态快照.md`
- `未解决伏笔.md`
- 已完成正文章节
- 用户手写的原始资料

如确需改动，应保留原内容或写入修订记录。

## 5. 文件读取规则

执行任务前，Agent 应读取最小必要上下文。

### 5.1 工作区级任务读取顺序

1. `_agent/novel-agent-system-design.md`
2. `_agent/operating-rules.md`
3. 与任务直接相关的路线图、模板或 skill 草案。

### 5.2 单本小说任务读取顺序

1. `00_项目总纲/项目说明.md`
2. `06_状态快照/当前上下文.md`
3. `06_状态快照/已确认设定.md`
4. 与任务相关的设定、角色、剧情或正文文件。

如果目标文件不存在，Agent 应说明缺失项，并根据任务性质选择：

- 创建空白模板。
- 让用户补充信息。
- 先只做规划，不写具体内容。

## 6. 状态快照规则

状态快照用于解决长篇创作中的记忆漂移问题。

每本小说至少维护：

- `当前上下文.md`
- `事实快照.md`
- `角色状态快照.md`
- `未解决伏笔.md`
- `已确认设定.md`

正文或大纲发生变化后，Agent 应列出可能需要更新的状态项：

```text
本次输出可能影响：
- 角色状态：
- 时间线：
- 伏笔：
- 已确认设定：
- 需要用户确认的变化：
```

用户确认后，Agent 再执行回写。

## 7. 设定层级规则

小说资料按优先级分为四层：

1. 已确认设定：最高优先级。
2. 事实快照：当前已发生或已写入正文的事实。
3. 待确认设定：可讨论，不可直接作为正式依据。
4. 灵感草稿：可参考，不可自动写入正文或大纲。

当不同文件发生冲突时，优先级如下：

```text
用户当前明确指令
  > 已确认设定
  > 已写正文
  > 事实快照
  > 章纲
  > 待确认设定
  > 灵感草稿
```

如果用户当前指令与已确认设定冲突，Agent 应指出冲突，并询问是否更新设定。

## 8. 正文生成规则

正文生成不是第一阶段重点，但为后续 skill 保留基本规则。

Agent 写正文前应确认：

- 目标小说明确。
- 目标章节或场景明确。
- 已读取当前上下文。
- 已读取相关角色状态。
- 已读取章纲或用户明确允许即兴创作。

Agent 写正文时不得：

- 私自改变核心设定。
- 为了制造爽点牺牲已确认人物逻辑。
- 使用另一部小说的设定或人物。
- 把参考资料原文直接搬入正文。
- 在未授权情况下跳过多个关键剧情节点。

正文输出后应：

- 标注草稿性质。
- 列出本次新增事实。
- 列出需用户确认的状态变化。
- 不自动覆盖已有章节，除非用户要求替换。

## 9. 审校规则

审校任务应优先发现问题，而不是急着重写。

审校输出建议包含：

```text
一、严重问题
二、连续性问题
三、角色逻辑问题
四、设定冲突
五、节奏与表达问题
六、建议修订方案
```

如果用户要求“直接改”，Agent 可以给出修订稿，但仍应说明改动范围。

## 10. 外部资料隔离规则

外部资料不得直接污染正式设定。

外部资料应按以下标签整理：

- `事实资料`：可验证的现实信息。
- `竞品观察`：对其他作品或平台趋势的观察。
- `创作灵感`：可能启发本书，但尚未确认。
- `写作方法`：结构、节奏、人物、叙事技巧。
- `工具参考`：GitHub 项目、软件、脚本、agent 设计。

只有用户明确说“采纳为设定”或“写入小说圣经”，外部资料才可进入单本小说的正式资料库。

## 11. Skill 草案管理规则

`_skills/` 目录用于维护本工作区内的 skill 草案。

每个 skill 建议使用以下结构：

```text
_skills/
  skill-name/
    SKILL.md
    evals/
      evals.json
    references/
    scripts/
```

Skill 草案必须包含：

- 名称。
- 触发场景。
- 任务边界。
- 输入要求。
- 输出格式。
- 需要读取哪些项目文件。
- 什么时候必须询问用户。
- 最少 2 个测试场景。

Skill 未成熟前，不急于安装到 Codex 全局 skill 目录。先在本工作区内测试，确认稳定后再安装。

## 12. 命名规则

### 12.1 工作区内部目录

工作区级目录使用英文下划线开头：

- `_agent`
- `_skills`
- `_templates`
- `_research`

### 12.2 单本小说目录

单本小说目录可使用中文书名。目录名应稳定，不建议频繁改名。

### 12.3 单本小说内部目录

单本小说内部目录使用数字前缀，方便排序：

- `00_项目总纲`
- `01_设定资料库`
- `02_角色资料库`
- `03_剧情结构`
- `04_正文草稿`
- `05_修订与审校`
- `06_状态快照`
- `07_参考资料`
- `08_导出`

## 13. 沟通规则

Agent 与用户沟通时应遵守：

- 先说明当前判断的任务类型。
- 文件改动前说明要改哪里。
- 遇到核心设定冲突时先停下确认。
- 不一次性抛出过多问题。
- 需要用户补充信息时，一次只问最关键的问题。
- 对长期规划任务，优先输出结构清晰的文档。
- 对执行型任务，优先完成文件落地和自查。

## 14. 错误处理规则

如果出现以下情况，Agent 应停止写入并说明原因：

- 找不到目标小说目录。
- 用户没有明确目标小说，但任务明显属于单本小说。
- 已确认设定与用户新指令冲突。
- 需要删除或覆盖大量已有内容。
- 外部资料来源不可靠，且用户要求写入正式设定。

如果只是缺少非关键文件，Agent 可以创建空白模板并继续。
