# 白描技法 Skill 增强设计

日期：2026-08-03

## 1. 目标

把 `文案文风/` 中的白描、视点、场景呈现和文字呼吸笔记转化为可执行、可检验的小说正文技法，同时保留原始文章，不把教学文章直接复制进 Skill。

本次增强必须让后续 Agent 明确理解三件事：

1. 白描适合解决什么正文问题。
2. 白描为什么能改善小说阅读体验。
3. 白描何时不应被机械使用。

## 2. 白描在本工作区中的定义

本次所说的白描，不是“完全不用修辞”，也不是“只写摄像机能拍到的内容”。它是一组以人物行动、物件状态、空间关系和有限视点为核心的场景呈现技法。

它的目标是让读者不用接受作者说明，也能从人物正在看、听、触碰、回避和选择的事物中形成连续画面，理解情绪与冲突。

白描主要带来以下价值：

- **空间落地：** 人物不再悬浮，读者能判断人、物与环境的位置及互动。
- **视点稳定：** 信息服从当前观察者的感知边界，减少视角漂移造成的出戏。
- **行动连续：** 把“发生了什么”的概括还原为可感知的动作、阻力和后果。
- **情绪共创：** 少替人物和读者下结论，让情绪通过动作、停顿和物件变化显现。
- **叙事提纯：** 删除重复解释，但保留必要的心理、概述、转场和叙述判断。
- **节奏呼吸：** 让句长、段落和信息密度跟随人物注意力变化，而不是机械切短句。
- **人物塑造：** 同一环境中，不同人物会注意不同细节、采取不同动作，因此白描也能显露性格和关系。

## 3. 使用场景

应主动使用白描模块的情况：

- 新写或重写小说场景，需要增强画面感、临场感或生活感。
- 人物只有表情和动作，却没有可辨认的空间与物件。
- 叙述连续介绍身份、动机、情绪和剧情功能，正文像故事说明书。
- 环境与外貌细节很多，但没有动作变化，正文像静态照片。
- 同一场景频繁越过当前人物的感知边界，视点漂移。
- 句子和段落信息过密，或者为了“快节奏”全部切成碎句。
- 异常、悬疑、冲突或情绪需要从正常生活细节中逐渐显现。

不应强制使用的情况：

- 必要的时间跨越、背景概述、心理反思和叙述转场。
- 用户明确要求高概述密度、寓言化、意识流或其他不同叙述策略。
- 逐场景展开会拖慢本应快速略写的次要事件。
- 为了“可拍摄”而删除小说独有的内心、记忆和自由间接叙述。

## 4. 架构

### 4.1 增强现有正文技法 Skill

继续由 `_skills/novel-prose-craft-keeper/SKILL.md` 负责正文技法总控，不创建与其争夺触发条件的第二个白描 Skill。

新增四个按需读取的参考模块：

- `references/white-description-space.md`：人物、物件与空间关系。
- `references/white-description-viewpoint.md`：视点边界与安全切换。
- `references/white-description-action.md`：作者解说、静态信息与动作连续性。
- `references/white-description-breathing.md`：信息主次、句段节奏与情绪留白。

`SKILL.md` 只保留白描的定义、价值、触发路由和总边界；详细规则、例子与检查问题放入对应参考文件，避免每次加载全部材料。

### 4.2 创建联想训练 Skill

创建 `_skills/writing-association-trainer/`，负责随机词发散、关联收束、情绪统一和练习点评。它不负责写正式小说正文，也不自动把练习结果写入任何小说项目。

### 4.3 暂缓内容

《救猫咪》文章暂不写入 `novel-plot-architect`，因为当前笔记没有完整列出十五节拍；网文市场文章暂不写入 `novel-research-scout`，等待来源核验和更完整的原创边界设计。

## 5. 调用流程

1. `novel-workspace-router` 定位目标小说与写入边界。
2. `novel-prose-craft-keeper` 读取项目文风、事实、章纲和目标正文。
3. 根据症状加载一个或多个白描参考模块。
4. 新写时交给 `novel-draft-writer`，重写时交给 `novel-revision-desk`。
5. 使用更新后的正文技法量表检查空间、视点、动作、呼吸和过度执行风险。
6. 保持正文与技法检查分离，不覆盖用户原稿，除非用户明确要求。

## 6. 规则校正原则

原始笔记中的教学说法必须经过以下转换：

| 原始倾向 | Skill 中的执行规则 |
|---|---|
| 摄像机拍不到的内容尽量删除 | 用“是否可感知”检查冗余解说，但保留有叙事价值的心理、概述和判断 |
| 同一场景不要切视角 | 默认保持视点稳定；确需切换时使用清晰的段落、场景或叙述信号 |
| 多写环境就有画面 | 只保留会约束行动、承接情绪或推动冲突的环境细节 |
| 拆分长句就有呼吸 | 让句段长度服从注意力、动作持续时间和情绪压力 |
| 少写作者旁白 | 删除重复解释，不取消作者叙述、主题判断和必要概括 |

## 7. 测试设计

修改前先建立失败基线，记录现有 Skill 在下列场景中的遗漏；修改后使用同样场景复测：

1. 悬浮人物：只有动作与情绪，没有空间关系。
2. 视点漂移：同一段落越过观察者的感知边界。
3. 解说过量：作者连续介绍身份、动机和情绪。
4. 静态堆砌：环境细节很多，但没有动作和状态变化。
5. 文字拥挤：信息、意象和长句同时堆积。
6. 机械短句：错误地把“呼吸感”理解为每句单独成段。
7. 过度白描：错误删除必要心理、概述或自由间接叙述。
8. 人物差异：不同人物应因经验与关系关注不同现场细节。

验收重点不是“用了多少动作和环境词”，而是：

- 读者能否建立连续空间。
- 信息是否遵守当前视点。
- 动作是否产生后果并推动判断变化。
- 情绪是否由可观察变化承接。
- 句段是否具有自然张弛。
- 白描是否服务人物、冲突和读者体验，而不是炫技。

## 9. 非目标

- 不修改 `文案文风/` 中的原始文章。
- 不创建六个相互重叠的白描 Skill。
- 不把白描设为所有小说、所有段落的默认唯一写法。
- 不处理具体小说剧情、设定或正文。
- 不在本阶段整合《救猫咪》和网文市场文章。
