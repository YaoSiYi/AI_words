# 小说工作区 Skill Roadmap

日期：2026-06-25

## 1. 总体策略

Skill 封装按“管理优先、写作后置”的顺序推进。

原因：

- 多本小说并行时，最先需要解决的是项目定位和资料隔离。
- 长篇创作的主要风险不是写不出一章，而是设定漂移、状态错乱和资料散落。
- 写作型 skill 必须依赖稳定的项目结构、状态快照和设定资料库。

## 2. 第一阶段：管理型 Skill

目标：让工作区稳定承载多本小说。

### 2.1 novel-workspace-router

职责：

- 判断任务属于工作区级、单本小说级还是外部参考级。
- 定位目标小说目录。
- 防止根目录和单本小说目录混淆。

优先级：最高。

验收标准：

- 用户在根目录提出任务时，能正确判断是否需要指定小说。
- 不会把具体世界观写进 `_agent/`。
- 不会跨小说混用设定。

### 2.2 novel-project-initializer

职责：

- 根据模板创建新小说项目。
- 初始化总纲、资料库、剧情结构、正文草稿、状态快照和导出目录。
- 只填入用户已提供的信息。

优先级：高。

验收标准：

- 新项目目录结构完整。
- 未知信息保持空白或待补充。
- 不编造人物、剧情或世界观。

### 2.3 novel-bible-manager

职责：

- 整理世界观、规则、角色、势力、地点和术语。
- 区分已确认设定、待确认设定和灵感草稿。
- 维护设定冲突记录。

优先级：高。

验收标准：

- 零散设定能被放入正确文件。
- 不把待确认内容写入 `已确认设定.md`。
- 能指出新设定与既有设定的冲突。

## 3. 第二阶段：结构与一致性 Skill

目标：让长篇创作不散。

### 3.1 novel-plot-architect

职责：

- 维护全书大纲、卷纲、章纲。
- 维护伏笔表、冲突链和时间线。
- 检查剧情因果是否成立。

验收标准：

- 能从已有设定生成结构化大纲。
- 能标记伏笔埋设与回收。
- 能指出剧情推进中的因果断裂。

### 3.2 novel-continuity-checker

职责：

- 检查角色状态、地点、时间、伤势、物品、能力和信息差。
- 发现设定冲突和状态漂移。
- 给出问题清单和修复建议。

验收标准：

- 能发现角色知道不该知道的信息。
- 能发现时间线和地点连续性错误。
- 能区分严重问题和普通修订建议。

### 3.3 novel-style-keeper

职责：

- 维护文风样本。
- 记录禁用表达和叙事偏好。
- 检查草稿是否偏离风格目标。

验收标准：

- 能从样本文本提炼风格规则。
- 能指出 AI 味表达和泛化句式。
- 不牺牲不同角色的语言差异。

## 4. 第三阶段：生产与交付 Skill

目标：提高正文生产、修订和导出效率。

### 4.1 novel-draft-writer

职责：

- 根据已确认设定、章纲和状态快照写正文草稿。
- 输出新增事实和状态变化。

验收标准：

- 不私自改变核心设定。
- 不跨小说调用设定。
- 每次输出后能列出需要回写的状态项。

### 4.2 novel-revision-desk

职责：

- 润色、压缩、扩写、增强对白和节奏。
- 区分语言修订、结构修订和剧情修订。

验收标准：

- 保留原意。
- 明确说明改动范围。
- 不在未授权时改变剧情结果。

### 4.3 novel-research-scout

职责：

- 检索公开资料、GitHub 项目、写作方法和竞品观察。
- 标记来源、日期和资料类型。
- 防止外部资料直接污染正式设定。

验收标准：

- 资料来源清楚。
- 能区分事实资料、竞品观察和创作灵感。
- 采纳为正式设定前会要求确认。

### 4.4 novel-export-packager

职责：

- 导出投稿版、存档版、docx、pdf、epub 或平台发布版。
- 整理章节标题、目录和基础格式。

验收标准：

- 输出文件放入 `08_导出/`。
- 不修改原始正文。
- 导出范围和格式清楚。

## 5. Skill 草案标准结构

每个 skill 使用以下结构：

```text
_skills/skill-name/
  SKILL.md
  evals/
    evals.json
  references/
  scripts/
```

`SKILL.md` 必须包含：

- `name`
- `description`
- 触发场景
- 输入要求
- 读取文件顺序
- 输出格式
- 必须询问用户的情况
- 不负责的内容
- 测试场景

## 6. 测试策略

每个 skill 初稿至少准备 2 个测试场景：

- 一个正常场景。
- 一个容易越界或误判的场景。

示例：

```text
正常场景：用户要求新建一本小说项目，提供书名和少量设定。
越界场景：用户在根目录要求写第一章，但没有指定小说项目。
```

测试重点：

- 是否正确分流任务。
- 是否读取正确文件。
- 是否避免编造缺失内容。
- 是否避免跨小说污染。
- 是否在核心设定变化前要求确认。

## 7. 当前推荐顺序

```text
1. novel-workspace-router
2. novel-project-initializer
3. novel-bible-manager
4. 用虚拟小说项目测试前三个 skill
5. 修订前三个 skill
6. novel-plot-architect
7. novel-continuity-checker
8. novel-style-keeper
9. novel-draft-writer
10. novel-revision-desk
11. novel-research-scout
12. novel-export-packager
```

## 8. 当前阶段建议

下一步应先起草 `novel-workspace-router`，因为它是所有后续 skill 的入口判断层。
