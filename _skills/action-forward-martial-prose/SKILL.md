# 动作先行武侠文笔

## 核心原则

只控制“怎么呈现”，不决定“发生什么”。

把章纲与项目资料中的事实转化为清楚、直接、可比较的正文画面：人物先行动，力量作用于具体物体，战斗围绕局势难题变化，情绪落在可见动作和具体牵挂上。

不得从参考作品借用人物、剧情、大纲、世界观、力量体系、专名、标志性表达或场景组合。

## 职责边界

本 Skill 负责：

- 句式节奏、段落呼吸和叙述距离。
- 空间定位、动作路径、接触点和物理后果。
- 战斗中的判断、受阻、反制和代价。
- 用环境、懂行人物或制度反应证明力量。
- 把抽象情绪落到动作、物件和选择。
- 检查正文是否过度解释、机械碎句或依赖围观者惊叹。

本 Skill 不负责：

- 设计主线、卷纲、章纲和结局。
- 创造项目正史、世界规则、人物命运或力量体系。
- 复刻任何单一作者的精确文风。
- 把外部作品的内容换名搬入原创项目。
- 替代项目路由、正文写作、修订或连续性检查。

## 必须配合的 Skill

- **项目定位：** 具体小说任务先用 `novel-workspace-router`。
- **项目文风：** 维护本书自身文风时用 `novel-style-keeper`。
- **新写正文：** 本 Skill 提供呈现约束，再由 `novel-draft-writer` 执行。
- **正文技法：** 同时使用 `novel-prose-craft-keeper` 保持呼吸感与人物生活。
- **重写旧稿：** 使用 `novel-revision-desk`，不得直接覆盖原稿。
- **事实核对：** 涉及已写章节和状态变化时用 `novel-continuity-checker`。

## 开始前读取

### 项目任务

按顺序读取存在的文件：

1. `00_项目总纲/项目说明.md`
2. `00_项目总纲/读者体验.md`
3. `00_项目总纲/禁止事项.md`
4. `05_修订与审校/风格修订.md`
5. `06_状态快照/当前上下文.md`
6. `06_状态快照/已确认设定.md`
7. 目标章纲、前一章结尾和相关角色文件

再读取：

- `references/style-profile.md`
- `references/originality-and-quality-rubric.md`

### 独立试写

没有绑定项目，只要求演示这种呈现方式时，读取两个 references 后允许生成“探索性试写”。必须明确标注：

```text
性质：探索性试写，不属于任何项目正史。
```

不得把探索稿写入任何小说的正式正文、设定、章纲或状态快照。

## 分离输入

写作前在内部区分四类输入：

| 输入 | 可以决定 | 不得决定 |
| --- | --- | --- |
| 项目设定与状态 | 世界规则、人物知识、时间地点、物品状态 | 句式和画面节奏 |
| 章纲与用户指令 | 场景目标、冲突、结果、伏笔 | 专属措辞和动作细节 |
| 本 Skill 与项目文风 | 叙述距离、句式、空间呈现、战斗因果 | 剧情事实和世界设定 |
| 外部作品分析 | 抽象、非专属的写作机制 | 人物、情节、专名、关系和场景顺序 |

发生冲突时，优先级为：

`用户当前明确指令 > 已确认设定 > 已写正文 > 状态快照 > 章纲 > 文风规则 > 外部分析`

文风不能推翻事实。

## 判断写作模式

### 模式 A：正式项目正文

需要同时具备：

- 明确目标项目。
- 足够的场景事实或已确认章纲。
- 可读取的项目边界与状态。

缺少其中任一项，不得把新内容当作正式正史。

### 模式 B：探索性试写

适用于：

- 用户明确要求演示文笔。
- 用户给出一句场景种子并允许自由发挥。
- 没有目标项目，且输出不会回写正史。

只建立完成场景所需的临时事实，不扩展完整世界观，不暗示这些设定已经被用户确认。

### 模式 C：风格重写

先列出必须保持不变的事实，再生成独立修订稿。不得改变：

- 场景结果。
- 人物命运与关系。
- 时间、地点、伤势和物品状态。
- 人物已经知道或尚不知道的信息。

## 场景执行流程

### 1. 提取场景脊柱

从用户或章纲中提取：

- 人物此刻要完成的具体事情。
- 现场首先妨碍他的东西。
- 失败会立即失去什么。
- 本场结束时必须改变什么。

找不到这些信息时，正式项目正文应停止；探索性试写可用最小假设补齐，并标注性质。

### 2. 建立空间

在冲突开始前让读者能回答：

- 人物站在哪里。
- 目标在哪里。
- 对手、障碍和退路在哪里。
- 哪件现场物体会参与动作。

不要写镜头术语。直接写人物能看见、触及、跨越或避开的东西。

### 3. 让力量可见

重要能力至少由两类证据确认：

- **物理证据：** 物件、距离、地形、伤势或速度改变。
- **专业证据：** 懂行人物看出难点、技巧或代价。
- **制度证据：** 职位、部署、谈判态度或群体行为改变。

围观者惊叹只能辅助，不能单独证明强弱。

### 4. 写出战斗因果

每轮有效交锋至少改变一项变量：

- 位置。
- 伤势。
- 时间。
- 武器。
- 信息。
- 底牌。
- 保护对象的安全。

重要战斗通常应经历：

`试探 → 受阻 → 修正判断 → 改写条件 → 关键反制 → 代价与余波`

这是检查顺序，不是必须逐段照抄的固定模板。不得为了满足结构而制造机械六段。

### 5. 调整语言

- 短句用于命中、转折、决定和真正停顿。
- 中长句用于连续动作、空间变化和情绪积累。
- 描写依附动作，不单独堆积华丽景物。
- 先给结果，再有限度解释。
- 同一强弱结论只保留最有说服力的证明。
- 情绪先落在手、脚、视线、停顿、物件和选择上，再决定是否点明。

### 6. 生成自然钩子

章末改变一项状态，并从本章结果自然引出下一问题：

- 新证据推翻旧判断。
- 胜利暴露身份或底牌。
- 保护目标暂时安全，但代价开始兑现。
- 人物做出不能轻易撤回的选择。
- 更高层力量已经进入现场。

不得使用与本章无关的陌生危机，也不得依赖“真正的故事才刚开始”等万能句。

## 原创隔离

禁止：

- 读取参考小说原文来临场贴句或仿句。
- 复用参考作品的专名、人物功能链、标志性物件或力量规则。
- 保留参考作品的事件起因、参与者功能、胜负方法和后续影响，只更换名字。
- 以“这是通用套路”为由复制连续场景顺序。
- 在正文中说明“像某作者”或“某作品式”。

需要借鉴时，只能从 `references/style-profile.md` 读取已经抽象化的表现机制。

## 输出约定

### 正式项目正文

```markdown
正文草稿：
[连续可读正文]

技法检查：
- 场景脊柱：
- 空间与动作：
- 力量证据：
- 局势变化：
- 情绪落点：
- 原创隔离：
- 事实风险：
```

保存到项目时，只把正文与必要元数据写入 `04_正文草稿/`；检查结果放在回复或 `05_修订与审校/`。

### 探索性试写

```markdown
性质：探索性试写，不属于任何项目正史。

[试写正文]

边界说明：
- 临时假设：
- 未借用内容：
```

## 停止条件

以下情况停止正式正文生成：

- 目标项目不明确。
- 缺少章纲或足够的场景事实。
- 用户要求精确复刻某位在世作者。
- 写作会改变已确认设定、人物命运或章节结果。
- 用户要求续写、改名搬运或复刻参考作品的情节。
- 无法确认某项内容来自项目资料还是外部作品。

停止时只询问最重要的缺失信息。若用户只是要独立演示，可切换为明确标注的探索性试写。

## 常见错误

| 错误 | 修正 |
| --- | --- |
| 没章纲也直接写成项目正史 | 改为探索性试写或先询问场景事实 |
| 用固定五拍、七段套所有场景 | 只检查因果变量，不固定段数 |
| 每个动作后解释为什么厉害 | 保留最关键的一次专业判断 |
| 所有强弱都靠群众震惊 | 增加物理或制度证据 |
| 只改参考作品的名词 | 重做目标、规则、解决方法和代价 |
| 为了快节奏连续碎句 | 用中长句恢复连续动作和空间 |
| 文风修订顺手改变剧情 | 先锁定事实，再写独立修订稿 |

## 写后检查

交付前完整执行 `references/originality-and-quality-rubric.md`。任一原创隔离红线命中，必须重写相关段落，不得只做表面换词。
