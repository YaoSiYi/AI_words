# 小说正文技法控制

## 核心职责

控制小说正文“怎么写”。让场景有人在里面生活，让异常从现实细节中长出来，让情绪在动作中递进，并阻止章纲、分镜、审核说明和短视频节拍直接混进正文。

本 Skill 不设计剧情结果，不改变正史，不替代正文写作、修订或连续性检查。

## 必须配合的 Skill

- **项目定位：** 小说目标不清楚时，先使用 `novel-workspace-router`。
- **文风提炼：** 需要从既有样本建立或更新文风时，使用 `novel-style-keeper`。
- **新写正文：** 使用本 Skill 约束技法，再使用 `novel-draft-writer` 写作。
- **重写旧稿：** 使用本 Skill 约束技法，再使用 `novel-revision-desk` 生成独立修订稿。
- **写后核对：** 涉及设定、时间线、物品或人物信息时，使用 `novel-continuity-checker`。

## 开始前必须读取

先定位目标小说，再读取存在的相关文件：

1. `00_项目总纲/读者体验.md`
2. `00_项目总纲/禁止事项.md`
3. `05_修订与审校/风格修订.md`
4. `06_状态快照/当前上下文.md`
5. `06_状态快照/已确认设定.md`
6. 目标章纲、前一章结尾和相关角色文件
7. 用户确认可作为文风样本的正文

如果目标是《一竿入梦》，还必须读取 `references/yi-gan-ru-meng-profile.md`。V1正文只提供文风与叙述技法，V2.1章纲和设定才提供当前剧情事实。

## 写作前分离四类输入

写作前在内部完成以下分离，不把分析过程写进正文：

| 输入 | 决定什么 | 不得决定什么 |
|---|---|---|
| 已确认设定与状态快照 | 世界规则、人物知识、时间地点、物品状态 | 句式和口吻 |
| 卷纲、章纲、故事基底 | 场景目标、冲突、结果、伏笔 | 正文段落和镜头切法 |
| 文风样本 | 叙述距离、节奏、生活细节、对白习惯 | 当前剧情事实 |
| 参考资料 | 专业事实和现实边界 | 未确认正史 |

如果四类输入互相冲突，优先保护已确认设定，并把冲突列在正文之后，不要偷偷修改。

## 场景发动方式

### 先确定场景脊柱

每个主要场景先明确：

- 人物此刻想完成什么具体小事。
- 现场哪个现实阻力先妨碍他。
- 哪个可见细节让原判断开始松动。
- 人物采取什么动作验证，而不是直接得出结论。
- 本场以什么变化、损失或未解决问题结束。

章节要像一段完整经历，而不是把章纲中的一个节点扩成若干短句。

### 给正文留下呼吸

呼吸感来自人物在主线动作之间仍然是活人：整理东西、嫌麻烦、嘴硬、走神、记错、停顿、观察旁人、被生活细节打断。只保留能加深人物、环境或悬念的岔开，不用无关闲聊灌字数。

不要机械规定每隔多少字出现刺激，也不要固定每段长度。紧张处可以短，观察和连续动作可以长，段落长短应随人物注意力变化。

## 画面感

### 用现场元素组成画面

优先从以下层次取材：

1. **物件状态：** 用旧、沾水、发热、缺口、气味、重量、摆放位置。
2. **人物动作：** 手先做了什么，脚站在哪里，动作是否迟疑或走样。
3. **空间关系：** 人、物、水面、灯光和声音之间的远近与遮挡。
4. **感官变化：** 声音突然少了、湿气贴上来、饵料味变淡、灯光被水吃掉。
5. **异常偏差：** 只改变一项本来熟悉的东西，让人物先察觉“不对劲”。

不要用连续形容词代替画面，不要一出现异常就给全景解释。

### 伪纪录片的正确位置

摄像机、录音和水下设备是现场中的物件，也是有限证人。它们可以遗漏、延迟、拍到人物没看见的细节，但不能变成作者的万能视角。

正文中避免：

- 连续交代推近、切换、特写、景别和机位。
- 用“镜头告诉观众”“画面完成反转”解释场景功能。
- 让无名摄制人员只负责提问，替读者索取答案。
- 把小说段落写成旁白、分镜或剪辑说明。

先让人物经历事件，再让影像在合适的时候补充或推翻人物判断。

## 情绪递进

情绪不是固定七步模板。根据场景选择四至六级连续变化，例如：

`平常或无聊 → 嘴硬 → 纳闷 → 不安 → 判断 → 犹豫 → 选择 → 余波`

每一级至少由一个可观察变化承接：动作变慢、话说到一半、手上重复无用动作、看错一次、改口、站位改变、丢掉原本想争取的东西。

避免直接写“他害怕了”“他意识到”“他内心复杂”。让读者从动作和对白里先感受到，再自己说出情绪。

高潮不是声音最大或异常最大，而是人物必须在两个都舍不得的东西之间作选择。核心表达从选择的代价中出现，不能由旁白总结成口号。

## 人物与对白

对白至少承担以下一项人物功能：维护面子、试探关系、回避真话、掩饰害怕、争夺决定权、暴露误判或改变关系。

纯信息问答连续出现时，改用动作、误解、沉默、打断或已有物件传递信息。不同人物不能共享同一种句式和吐槽节奏。

方言只落在情绪点和人物习惯上，不整段翻译成方言，也不靠口头禅替代人物塑造。

## 句式与段落

- 长短句混用。短句用于落点、突变和迟疑，长句用于连续动作、空间观察和情绪积累。
- 单句成段必须有真正的停顿价值，不能把每句话都切成鼓点。
- “不是A，是B”“先A，再B”“他看了看”“这很重要”等模板可以偶用，连续出现必须改写。
- 少用作者总结，多保留人物的局部判断和可能出错的观察。
- 允许句子带一点人的毛边，但不能故意制造语病冒充人味。

## 章节容量

优先服从项目自己的章节规模。没有明确标准时，网文章节可参考约1800至2800字，但字数不是验收目标。

章节至少应具备：具体开场、一次现实行动、一次判断变化、一次人物关系或情绪变化、一个由前文生长出来的结尾余波。不要为了凑章数把同一场景拆成多个只有一个信息点的短章。

## AI味高风险信号

出现以下情况时，先修正文再交付：

- 段落长度和句子节奏过于整齐。
- 连续使用对举、排比、三段论和总结句。
- 每个动作后都解释其意义。
- 对白像采访问答，所有人都在帮助作者讲设定。
- 场景没有无用但真实的生活动作。
- 异常升级只靠更大、更亮、更响。
- 章末使用泛化的“更深黑暗”“真正开始”“无人知道”等万能钩子。
- 正文出现“传播线、价值线、证据链、节拍、镜头锚点、用户、观众”等生产术语。

## 写后检查

完成初稿后，读取 `references/prose-craft-rubric.md`，进行一次独立检查。检查说明放在正文之后，正文中不出现自评术语。

至少回答：

1. 本章最有生活感的三个细节是什么？
2. 情绪从哪里开始变化，每一级由什么动作承接？
3. 哪些句子只是在解释章纲功能？删除后是否更好？
4. 摄像设备是现场物件，还是已经控制了叙事？
5. 对白是否带人物关系和潜台词？
6. 是否出现连续碎句、模板对举或万能钩子？
7. 是否保持了剧情事实、人物信息边界和物品连续性？

## 输出约定

正文与检查分开：

```markdown
正文草稿：
[连续可读的小说正文]

技法检查：
- 画面锚点：
- 情绪递进：
- 人物声音：
- 呼吸感：
- AI味风险：
- 事实风险：
```

保存正文时，只把小说正文和必要的章节元数据写入 `04_正文草稿/`。技法检查优先写入回复或 `05_修订与审校/`，不要混进正文文件。

## 停止条件

以下情况先停止正文生成：

- 找不到目标小说。
- 没有章纲或足够的场景事实，用户又未授权探索稿。
- 用户要求保持项目特定文风，但没有任何可用样本或规则。
- 重写会改变剧情结果、人物命运、时间线或已确认设定。
- 用户要求覆盖既有正文，但没有明确覆盖范围。
